## 三、必答问题

### 问题 1:提取脚本怎么处理 Dart 转义?逐类说明。

脚本用「单遍扫描」实现:**遇到 `\` 就吃掉它,并按后一个字符决定输出;遇到 `$` 就判断是否插值**。逐类:

| 转义类 | 是否出现在 shell 内 | 脚本怎么处理 | 依据 |
|---|---|---|---|
| `\$` → `$` | **有**,1 处(第 3559 行 `"\$("`) | `\`+`$` 输出 `$` | 字节 dump:源文本 `5C 24`;`dart run` 实证 `\$`→`$` |
| `\\` → `\` | **有**,多处(`<\/script>`、`\{\{user\}\}`、`\/body`) | `\`+`\` 输出 `\` | 字节 dump `5C 5C`;`dart run` 实证 |
| `\/` → `/` | **有**,1 处(第 3796 行 `\\\/body`,三反斜杠 = `\\`+`\/`) | 先 `\\`→`\`,再 `\/`→`/` | `dart run` 实证 `\\\/`→`\/`;`dart analyze` 也在 3796 报 `unnecessary_string_escapes`,旁证该 `\` 是"多余转义" |
| `\{` / `\}` → `{` / `}` | **有**(regex `\{\{user\}\}` 中的 `\\{` `\\}`) | `\`+`{` 输出 `{`(同理 `}`) | `dart run` 实证 `\\{`→`\{` |
| `\'` / `\"` | **无**(三引号里单双引号不需转义) | 走默认分支:输出该字符 | 防御性保留,shell 内未出现 |
| `\n` / `\r` / `\t` / `\b` / `\f` / `\v` | **无**(shell 换行是真换行符) | 输出对应控制字符 | 全 shell 范围 grep `\n`/`\r`/`\t`/`\u` 无命中 |
| `\uXXXX` / `\xXX` | **无** | **未特殊处理**(若有会产出错误文本) | 全 shell 范围 grep 无命中;脚本注释已显式点名此局限 |

关键实证(临时脚本 `dart run` 输出,原样):

```
A=[if (/<\/body>/i.test(html))]
B=[html.indexOf("$( ")]
C=[+ "<\/script>"]
D=[t.replace(/\{\{user\}\}/gi,v.user)]
```

大白话:shell 里实际只用三种带反斜杠的东西——`\$`、`\\`、以及 `\\`+`\/`,其余转义一概没有。我每一种都既抓了原始字节、又跑 Dart 复现了结果,不是靠"应该"猜的。

### 问题 3:动态插值处怎么处理的?会不会导致 node --check 误报?

- 两处颜色 `${...}` → 替换成 `__DART_INTERP_QUOTE_Q_COLOR__` / `__DART_INTERP_QUOTE_P_COLOR__`,**落在 `<style>`(CSS)里**。而 `node --check` 只检查 JS(脚本只从 `<script>` 块抽 JS,CSS 根本不进 `.js`),这两个占位**不可能**影响 `node --check`。
- `$kChatBridgeJs` → 用**真实桥 JS**内联,前后只加 `/* ... */` 注释(合法 JS)。所以它不但不制造误报,反而让检查**更严格**:连桥 JS 语法也一起验了。

结论:占位符不会导致 `node --check` 误报;通过 = 真通过,没有"注水"成分。

大白话:三个洞里,两个是颜色(只影响 CSS),一个是桥代码(用真货填进去还顺带检查了它的语法)。机器检查的结果是干净可采信的。

## 五、一个必须交代的事实:源码换行是 CRLF + 带 BOM

对源文件做字节统计:

```powershell
CRLF pairs    = 4753
Has UTF-8 BOM = True
```

并用一个 CRLF 小样例 `dart run` 实证:**Dart 会把三引号字符串里的 CRLF 归一化成 LF**(打印出的 `codeUnits` 没有 `13`(CR),只有 `10`(LF)):

```
[104, 101, 108, 108, 111, 10, 119, 111, 114, 108, 100, 10]
```

所以:
1. 提取脚本读文件后 `.replaceAll('\r','')`、再按 `\n` 拼回,与 Dart 实际生成的字符串值**逐字节一致**(都是 LF),不是"我以为一致"。
2. 源文件头有 UTF-8 BOM,但 BOM 在第 1 行 `import` 之前、不在 shell 字符串内,不影响提取;产物用 `Utf8Codec()` 写出,不含 BOM。

大白话:源文件是 Windows 的 CRLF 带 BOM;我先搞清楚 Dart 会把它"折"成 LF,才敢说"产物等于运行时真实字符串",这是诚实核对的一步。

## 七、我没能验证的部分

1. **`node --check` 只验语法、不验运行**:不查"未定义引用/空指针/逻辑错误"。所以"语法合法"≠"跑起来没问题";`sendToFlutter`/`registerBridgeHandler` 等运行时对象一律不查。这是这条尺子的边界。
2. **没有真机/模拟器运行**:产物没灌回 WebView 做过真实渲染,"行为不变"是静态推断。
3. **`dart analyze` 完整 1092 行既有 warning/info**:逐行 grep 确认 error=0、warning=679、info=413,且 `webview_chat_stage.dart` 只有 `info`(3062、3796 等);但未逐条阅读全部 1092 行。
4. **BOM/编码在 release 打包下的差异**:只实证了 Dart 字符串层面 CRLF→LF;asset 在 Android/iOS release 打包里的编码行为(会不会被加 BOM)未验证,留给 P0-3「诊」。
5. **一次性提取脚本的锚点搜索脆弱性**:脚本靠 `String _htmlShell() {`、`const String kChatBridgeJs = r'''`、`''';` 这些内容锚点定位;一旦源文件再出现同类锚点文本,脚本可能误判。当前文件内无冲突(已核查),但脚本不自检这一点。
