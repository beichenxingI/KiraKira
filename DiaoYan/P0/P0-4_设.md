## 4-4 施工顺序与安全网

### 顺序

1. **最前置**`:确认基线干净(git status 无意外改动 / dart analyze 与基线一致)。
2. **第 1 个 commit**:加两个 asset;立即用 P0-2 提取脚本对 `chat_stage.html` 做一次端到端抽取 → `node --check build/shell_extracted.js` 必须 exit 0;再 `dart analyze` 确认无新 error。
3. **第 2 个 commit**:改 `webview_chat_stage.dart` 的三处;**立即**内容等价自检 —— 利用脚本修改一处锚点(只做核对用,不入库),让 `_htmlShell()` 输出"拼装后的完整 HTML",跑 `node --check` 应 exit 0,并匹配除了三个占位符外与原字面量逐字一致(可由脚本在拼装即出后做"占位符已全替换"的 assertion)。
4. **停止手改逻辑**,仅做格式对齐(prettier/等宽),如需即追加一个纯格式 commit。

### 安全网(每步炸之后回退)

- 第 1 个 commit 出问题:删除这两个 asset 即可回到基线(`git reset --hard HEAD~1` 或只删新文件);没有任何业务代码依赖它们。
- 第 2 个 commit 出问题:`git revert <commit2>`(=`git revert HEAD` 若直接落在该 commit 上),恢复 Dart 旧逻辑;assets 保留于仓内,下次复用。
- 若需即时回滚又不方便 revert:仅把 `_chatStageHtml` 的读取改为"读不到即用错误页",不会出现"空白装载",已能在失败时可见。

## 4-5 复测说明(给人类)

- **重启要求**:本改造动了 assets 与 Dart 逻辑,务必使用**冷启动/重启**(不是热重载);热重载对 asset 路径与 init 串行的行为未验证(P0-3 已注明)。
- **看什么、点哪里**:
  - 打开 app 进入已登录的聊天页;
  - 期待:正常渲染历史消息与模型列表;
  - 在主界面点"切换模型"/"功能面板"等,能触发 `showModelSheet`/`openFunctionPanel` 的功能;
  - 观察是否有显眼的错误页(如果出现,则资产丢失 → 回退);
  - 观察引号颜色是否和改动前一致(若缺失主题色,说明颜色占位替换失败);
  - 观察日志中是否出现 `[聊天壳]` error;
  - 观察是否出现`no JS handler`、`[dispatch错误]` 等桥异常日志';
- **成功 vs 失败的判定**:
  - 成功:聊天页正常显示、桥通行无阻、主题色正确、无 `[聊天壳]` error。
  - 失败:空白或错误页、模型/list 不渲染、桥不通;此时:
- **失败时抓什么日志给谁看**:保留 app 运行日志(包含 `[聊天壳]` 与 `[bridge]` 系列);保存 `build/shell_extracted.js` 的 `node --check` 输出与 diff;把日志与 diff 一并给审核人。

## 4-6 我没能验证的部分(诚实列举)
