# P0.5 — 重建 JS 语法检查链(P0 收尾)

> 目的:`tool/extract_shell.dart` 从 `webview_chat_stage.dart` 的三引号字面量提取 JS,
> 但该字面量已在 commit `903b20c` 迁入 asset → 原脚本数据源消失,检查链断了。
> 本步新建 `tool/check_chat_stage.dart`,改读 asset,把壳里所有 `<script>` 块逐块跑 `node --check`,
> 并用「故意破坏→抓错→撤销复验」自证这把尺子真的能抓错。

---

## 一、为什么选 Dart(而非 .js)

- 仓库 `tool/` 下已有 3 个 Dart 脚本(`extract_shell.dart`/`gen_chat_assets.dart`/`apply_p0_5.dart`),`dart run tool/...` 是既有惯例,本脚本沿用,风格一致。
- Dart 的 `dart:io` 提供 `Process.runSync('node', ['--check', path])`,一次调用直接拿到 `exitCode`/`stdout`/`stderr`,比 Node 里再 spawn 子进程更简洁。
- 不引入新的运行时依赖(Node 只是被脚本调用的外部命令,和 `node --version` 同一条 PATH)。

## 二、脚本工作方式(关键点)

`tool/check_chat_stage.dart`:

1. 读 `assets/chat/chat_stage.html`(只读)、`assets/chat/chat_bridge.js`(只读)。
2. **桥占位符处理**:把单占一行、本身不是合法 JS 的 `__KIRA_CHAT_BRIDGE__` 用
   `html.replaceAll('__KIRA_CHAT_BRIDGE__', bridge)` 换成 `assets/chat/chat_bridge.js` 真实内容
   —— 与运行时 `_htmlShell()` 里那条 `replaceAll` **完全相同**,顺带把桥也一起验证。
3. 用 `<script>([\s\S]*?)</script>` 抽出**所有** script 块。实测正好 2 块:
   - block 1 = `<head>` 里的 polyfill(asset 第 5–31 行)
   - block 2 = `<body>` 末尾主脚本(asset 第 338–1513 行,含替换后的桥)
4. 每块写到 `build/check_block_N.js`,逐个 `node --check`。
5. 汇总:全通过 → 打印 `SYNTAX OK (N blocks)` 并 exit 0;任一块失败 → 打印块号 + node 的 stdout/stderr 原始输出,exit 1。

> 颜色占位符(`__KIRA_QUOTE_Q_COLOR__`/`__KIRA_QUOTE_P_COLOR__`)在 `<style>` 里、不进任何 script 块,无需处理。
> `build/` 为构建产物目录(gitignore 覆盖),临时 `check_block_*.js` 不入库。

## 三、日常检查命令(以后每次改 JS 都跑)

```powershell
dart run tool/check_chat_stage.dart
```

- exit 0 = 全部 script 块语法合法(PASS);
- exit 非 0 = 有语法错,输出里会标明**哪一块 + node 原始报错**。
- PowerShell 里查退出码:`dart run tool/check_chat_stage.dart; echo $LASTEXITCODE`

## 七、我没能验证的部分

1. **node 版本差异**:本机 `node v24.13.1` 跑通;旧版 node 的 `--check` 参数与报错文本格式是否一致未验证(该参数 Node 长期支持,但报错措辞可能随版本变,不影响"exit 码"这个核心判定)。
2. **`<script>` 正则对各种极端壳结构的鲁棒性**:当前壳结构(2 块、桥内无 `</script>`、字符串内闭合标签都是 `<\/script>` 带反斜杠)已确认正则能精准匹配;将来若有人往 main script 里塞入不带反斜杠的 `</script>` 字面量串,正则可能被提前截断——**未验证**,属已知边界(脚本用了非贪婪匹配,已经是对最坏情况最保守的处理)。
3. **真机/模拟器**:本步纯命令层面验证 JS 语法,未跑 app。`node --check` 只验语法、不验运行(与 P0-2/P0-5 同一边界)。
4. **`__p0_broken` 注入法 vs 指令例示的"删右花括号"**:两者都是语法错,注入法更易精确定位与撤销;效果等价(node 均以非 0 exit + SyntaxError 抓出),但严格讲不是逐字照做指令里的那个例子。
