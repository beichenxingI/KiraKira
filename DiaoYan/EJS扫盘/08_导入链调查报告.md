## 二、character_book 断点定位

链路:PNG chunk → JSON → `_parseCharacterBook`(ImportService)→ Character(entries)→ `_importAllCharacters` 判断 `entries.isNotEmpty` → `importEmbeddedLorebook` 建书+逐条 addEntry。

**断点最可能在解析→判空这一环【高嫌疑】**,三处证据:
1. `_parseCharacterBook`:`json['entries'] as List<dynamic>? ?? []` —— **entries 若是字典形态(Map),强转失败→null→静默变 0 条**。上游部分导出器(Agnaistic/某些 chub 卡)确实写字典。models.CharacterBook.fromJson 同病。
2. `_importAllCharacters`:`entries.isNotEmpty` 不满足 → 跳过 importEmbeddedLorebook → **只剩 addCharacter 自动建的"XX 的世界书"空壳**(commit 42829f9 新增)——与人类所见完全一致。
3. 即便条目进来,`importEmbeddedLorebook.addEntry` **不传 constant/insertionOrder/caseSensitive/enabled**:带 keys 的条目会被 addEntry 默认成 constant=false(addEntry 内部:keys 非空时 constant 默认 false)——**新卡 probe(constant:true)即使导入也会退化成关键词触发**,这解释了为何 probe 类条目必须靠"条目根本没进"来解释;旧卡 initvar 能出现说明旧卡走的通且其触发条件恰好满足。

次要候选(探针会一并排除):PNG 多文本块取首个可解析者(v2 chara 与 v3 ccv3 并存时可能取到旧的那份);zTXt 压缩块静默跳过。

## 三、角色正则去向

- 存储侧【实证】:data.extensions.regex_scripts **已随 extensions 整包落库**(extensionsJson),数据没丢!
- 桥接侧【确诊缺陷】:聊天时 `CharacterRegexScriptsNotifier._loadScripts` 读 `character.extensions['regex_scripts']`,但用 **自家 `RegexScript.fromJson`** 硬 cast(`id as String`、`scriptName as String`、placement 按**枚举名**匹配);上游卡是 ST 格式(数字 placement、snake_case 备选键)。类型不齐 → map 中途抛 TypeError → 被 try/catch 吞 → **state=[] → 正则全灭**。模型里现成的 `RegexScript.fromSillyTavernJson`(数字 placement 映射都写好了)**没被这条链使用**。
- ai_presets_screen.dart:256 另有一处正确用 fromSillyTavernJson 的正则导入(preset 路径),佐证"正确工具已有、桥接点用错"。
- TavernHelper_scripts / depth_prompt / talkativeness:随 extensions 落库但零消费【沉睡】。

## 四、system_prompt 缺席:代码缺陷(非开关)

【实证】默认 PromptManagerConfig 给 systemPrompt section **预填了通用内容**(`content: getDefaultContent(...)` = "你正在与{{user}}进行一场虚构的角色扮演对话…")。而组装逻辑:
```dart
final content = section.content?.isNotEmpty == true
    ? section.content!              // ← 默认通用指令恒非空,恒胜出
    : character.systemPrompt;       // 角色卡 system_prompt 永远轮不到
```
人类 11 条 messages 里的"通用扮演指令"正是这个 section 的默认 content——**section 开着、也在发,只是发的是默认文案**。上游语义应为"卡有 system_prompt 用卡,没有才用默认",此处优先级写反。修法方向(下轮):content 为空才覆盖的判定改为「section.content 与默认文案不同(用户真改过)则用之,否则角色卡优先」或引入 override 标记。

## 五、11 条 messages 逐条归属(_buildContext 组装序)

1. 通用扮演指令 = systemPrompt section(**默认 content,卡 system_prompt 被压**)
2. user名 = persona section
3. Description = characterDescription section
4. Personality = characterPersonality section
5. Scenario = characterScenario section
6. 世界书条目 = WI(before/after position 注入,来自世界书表——注入链健康)
7. 开场白(assistant)= chatHistory 第 0 条
8. user输入 = chatHistory 末条
9. 结尾越狱 note = postChat/depth section(postHistoryInstructions 或自定义越狱段)

对齐结果:除 systemPrompt 被默认文案顶替外,**没有发现其它本应出现而缺失的段落**;exampleMessages section 未出现在人类清单里(该卡可能没配 mes_example,或 exampleMessages section 关闭——探针 IMP-2 会给出 len,可对照)。

## 六、v1/v2/v3 分支

【实证】判定 = `containsKey('spec') && containsKey('data')` → V3/V2 标注版;只有 `data` → V2;都没有 → V1 扁平。无 spec 字段的 V2 卡走第二分支,字段解析相同。**不存在"只走 v1"的系统性问题**;V1 天然没有书/正则/system_prompt。注意 PNG 解析器按 chunk 顺序取第一个能解出且含 name/data/description/spec 任一 key 的块——同卡双份(chara+v3)时取谁看运气,探针 IMP-1 打出的顶层 keys 可判。

## 九、给人类的一句话操作说明

**重新导入一张"丢条目"的新卡(先删掉旧的那张),然后 grep `E"IMP-[0-9]"`:**

- `[IMP-3] entriesRawType=Map` + `!! DICT-FORM` + 后续 `[IMP-5] SKIPPED entries=0` → **确诊字典形态条目被吞**(下轮修解析器兼容 Map);
- `[IMP-3] entriesRawType=List count=N>0` 但 `[IMP-5] SKIPPED` → 判空条件/传递链断,把这几行发给 agent;
- `[IMP-5] FIRED` 且逐条 `addEntry` 都打了、但 `[IMP-6] entriesInDb=0` → 落库/外键问题(agent 查 worldInfoId);
- `[IMP-6] entriesInDb=N` 正常但聊天里 probe 仍不出 → 看该条 `constant=false`(已知降级缺陷)+ WI 注入侧;
- `[IMP-7] LOAD FAILED: TypeError...` → 正则桥格式错配确诊(下轮换成 fromSillyTavernJson);
- `[IMP-4] regexScriptsCount=null` → 这张卡本来就没带正则(不是我们的锅)。
