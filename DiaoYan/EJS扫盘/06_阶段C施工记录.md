## 一、三条施工前补验结论

### 1. 镜像新鲜度:有洞,已在 Task 2 内修复
【实证】`_syncVarsToEngine` 仅两处调用且都在 `_handleSetVariables` 内(message/chat 分支);**global 写分支不同步**;引擎房重建(resetEngineRoom)后镜像从空开始;Flutter 宏({{setvar}} 等)写的变量**从不进镜像**。
→ 渲染时刻若只靠既有链路,EJS 会读到空值或上一轮残留。
→ 修法:Task 2 的 kick 脚本在触发 evalTemplate **之前**,把 Dart 权威快照(global + chat + 最后一条消息当前 swipe 的 stat_data)以 `__varSync` 同形内联赋值进镜像(`_TH.__varCache` 三层 + extension_settings.variables.global + chat_metadata.variables + chat[mid].variables[sid])。同步与渲染同脚本同帧执行,无 postMessage 竞态。

### 2. 回灌方向:无自动回灌路 → 不停工,无需快照隔离
【实证】`__varSync` 单向(Dart→镜像):唯一发送方是 Dart 的 `__syncVarsToEngine`,唯一消费方是 facade 监听器(只写镜像)。镜像→DB 只剩显式桥调用:setVariables/replaceVariables/updateVariablesWith(th_setVars)、setChatMessages(th_setMessages)——均为 MVU 主动写 API,渲染本身不会触达。
边界备案:模板若显式调 dist 暴露的 saveVariables() 会走桥落库——这是上游 ST-Prompt-Template 同款设计(卡片作者主动持久化),非渲染副作用,风险接受并记录。
附:`_TH.getAllVariables` 在外层 typeMap 无映射 → 死桩,无风险。

### 3. 跨 frame Promise:Plan B 升为主案
按人类指示,Task 2 直接以 kick+poll 落地:kick 脚本同步返回 seq id(number),iframe 回调把结果写进外层 `window.__krRes` 槽,Dart 每 20ms 轮询读取(上限 8s)。**全程不依赖 evaluateJavascript 对 Promise 的解析**,老 WebView 也稳。跨 realm 仅剩 `.then()` 对 iframe Promise 的结构化调用(thenable 语义,引擎无关)。

## 三、人类真机验收脚本(V0-V5 + 特征值验证)

准备:一张带 `<initvar>` 开场白和变量条件模板的高星卡;没有现成卡就在世界书/system 里注入测试条目:
```
测试 <% if (1+1===2) { %>EJS活了<% } %> 当前好感 <% if (typeof getvar==='function') { %>(getvar可用)<% } %>
```

- **V0 · P5/P1 回归**:冷启 app → 直接进聊天发一条消息 → 设置页看全局旧变量未丢;新建带 initvar 开场白的聊天 → 日志搜 `ReferenceError`(应为 0 条)、搜 `setVars落点`/`swipes_data`(应见 stat_data 有值)。
- **V1 · 引擎房健康**:进聊天页 → 日志应出现「[引擎房] EJS 模块已注入」,不再出现「EJS 注入失败: ReferenceError」。
- **V2 · evalTemplate 通路**:发普通消息 → 无 `[EJS渲染错误]` 日志即通路正常;若每条都秒回原文且无错误,说明走了 -1 回退(EjsTemplate 未就绪),把日志级别拉出来看「EJS路径替换 命中X/16」是否为 16/16。
- **V3 · 控制流真活(核心)**:**开 LLM 请求日志**(llm_service 自带完整请求 dump),在发给模型的 messages content 里确认 `<% %>` 标签已被求值(如「测试 EJS活了」),而不是原始标签。
- **V3.5 · 镜像新鲜度特征值验证**:先用设置页或 {{setvar}} 把某局部变量设成特征值(如 `好感度=77`)→ 发消息 → 请求日志里模板分支应读到 77(证明快照注入生效,而非读到空/旧值);再改值为 88 再发一轮,确认变化跟随。
- **V4 · MVU 共存回归**:同一轮对话 MVU 状态栏照常更新:日志有 `[点火] message_received`、`[setVars落点]`;变量面板数字累加正常(generation_started/message_received 点火频率未被触碰)。
- **V5 · fail-open**:故意写坏模板(`<% if( %>`)→ 发消息不炸、正常收到回复、日志出现 evalTemplate 失败回退记录。
