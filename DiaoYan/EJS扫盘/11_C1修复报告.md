## 二、Task 2 方案选择:α(整消息单 iframe)

**上游核实结论**:ST 把消息 HTML 经 jQuery `.html()` 注入**同一个 document**——同消息内多个 `<script>` 块共享同一全局作用域(var/function 提升、互相可调用);跨消息同样共享(ST 不隔离)。播放器+点击控件+状态栏互相调用的写法在上游是常见依赖。→ **β(每段一 iframe)会切断这种耦合,排除;α 是唯一正确选择。**

实现:
- Dart 步④重写为**顺序切段器**:` ```html 围栏`、`<!DOCTYPE/<html 文档`(至 </html>)、含 `<style|<script` 的裸富块 → `[文本段,HTML段,文本段,…]`,保持原序、不丢不重;文本段照旧走 markdown+高亮。
- 载荷新增 `segs:[{h:bool,v:string}]`;旧字段 prose/html 继续填充(纯文本回退 markdown 整段)=**回滚通道**。
- Shell 渲染:有 segs → **一个 iframe** 内按序拼接全部段落(文本段也在内,附基础排版 style),共享作用域;无 segs → 走旧路径。旁白 prose 在 α 下并入 iframe,不再单独气泡。

**iframe 数量风险(α 且本轮不做窗口化)**:iframe 数 = 带 ≥1 富段的消息数;纯文本消息仍是主文档轻气泡不计入。100 条全富聊天的极端情形 ≈ 100 个 blob iframe——内存与渲染压力会重新抬头(WV-5 nodes/cardIframes 可观测)。缓解现状:text-only 免疫;真书卡通常少数楼层带前端。**若复测见 cardIframes>50 或再触发 WV-6,下一轮立即启用调查 C 方案一的窗口化。**
