# 02 · 高危交叉点清单 —— EJS 与 MVU 共用雷区(阶段 C 排雷手册)

> 每条注明:动它会波及谁、为什么危险。标记同前。
> 这份是排雷手册:阶段 C 动手前先对着它过一遍。

---

## X1. _TH.__varCache + 三标准对象同源回填(facade)

- 位置:tavern_helper_facade.dart「变量镜像(同步读)」与「收外层推来的真实变量 → 回填镜像」段。
- 谁在用:MVU 的 getVariables/getLastMessageId(同步读镜像);EJS dist 经 stub 读 extension_settings/chat_metadata/chat[].variables;updateVariablesWith 写后回填。
- 动它的波及:EJS 与 MVU **同时致盲或同时看到脏数据**。镜像与 DB 无一致性保障(写镜像成功、落库失败不回滚)。改回填结构时必须三层(global/chat/message[swipe_id])一起动。

## X2. _handleSetVariables(th_setVars 单点)

- 位置:webview_chat_stage.dart「酒馆助手 setVariables」。
- 谁在用:MVU replaceVariables/updateVariablesWith/setVariables 全部经 typeMap 收敛到这一个 handler;外层消息卡 iframe 的变量写也走这里。
- 危险【实证】:setVariables 与 replaceVariables 同路;message 层整份替换 vs chat/global 层逐 key 合并的语义分裂都在这个函数里。动定位逻辑(message_id 缺失落最后一条)会直接改变 MVU 变量落点——这是「变量写到上一楼/丢失」类 bug 的唯一嫌疑地。

## X3. _serializeMessagesForMvu(MVU 世界观定义者)

- 位置:webview_chat_stage.dart「给 MVU 用的消息序列化」。
- 谁在用:generation_started/message_received/chat_changed 三处点火全部用它喂 __chatMessages;MVU 的消息遍历、getLastValidVariable 回溯、initvar 抽取全靠它的字段形状(swipes/variables/swipes_data/message_id/swipe_id)。
- 危险:第 0 条空 MvuData 基座的注入逻辑在这里——删掉它空卡变量更新全灭(isMvuData 校验不过);改字段名会让 MVU 静默拿不到数据(bundle 是黑盒,不报错)。
## X4. VariablesService 单例(Flutter 宏与 WebView API 的共同地基)

- 谁在用:MacroService(prompt 组装+开场白)、chat_providers processMacros、th_getVars/th_setVars(global/chat 分支)、设置页。
- 危险【实证】:全局变量懒加载(见 03 P5)——WebView 侧写全局变量时如果 Flutter 侧还没加载过,SP 旧存档会被「空表+新 key」整体覆盖。任何动 VariablesService 初始化时序的改动都是高危。

## X5. generation_started / message_received 点火时序

- 位置:webview_chat_stage.dart _sendMessage、isGenerating watcher、进入聊天 chat_changed。
- 谁在用:MVU initCheck(generation_started)与新回复变量解析(message_received)的唯一驱动;reroll/继续/群聊等路径是否都经过 watcher 未逐一验证【疑似】。
- 危险:双发问题(03 P4)——动 watcher 或 _sendMessage 任一处都可能让 MVU initCheck 跑两次或零次;swipe 重掷走哪条点火链当前不明。

## X6. ejs_stub.js 的 chat Proxy 活引用

- 位置:ejs_stub.js 开头「Proxy 活引用」段。
- 谁在用:EJS dist import 的 chat;__thEvent 灌数据时整体替换 window.chat 内容,Proxy 让 dist 无感刷新。
- 危险:Proxy 只代理了数字键/length/函数绑定,fallback 直接读目标对象;若 dist 用 in/hasOwnProperty/Object.keys 遍历 chat 可能行为偏差【待验证】。改 stub 导出面 = 同时改 dist 与 MVU 可见的 ST 世界。

## X7. tavern_events 常量表(两份!)

- 位置:tavern_helper_facade.dart(facade 版)与 webview_chat_stage.dart 外层脚本(另一份,内容略少)。
- 危险【实证】:两份手工拷贝已经不同步(外层版缺 CHAT_COMPLETION_* 等)。改事件名/补常量必须两处同步,否则 facade 世界与外层世界对同一事件名认知分裂。MVU/dist 读的是 facade 版。

## X8. swipesData(MvuData)结构契约

- 谁在用:Dart 兜底基座(_serializeMessagesForMvu)、MVU isMvuData 校验(stat_data+schema 双必需)、_handleSetVariables 整份替换、显示域 setMessages 下发。
- 危险:字段是黑盒 bundle 校验的,Dart 侧只按约定造形。加字段安全,删改 stat_data/schema/initialized_lorebooks/delta_data/display_data 任一名字都可能让 MVU 静默丢弃整个本子。

## X9. facade 身份谎报组

- getTavernHelperVersion 返回硬编码 "4.9.1";getScriptId/registerAsUniqueScript/th_unique_check 假身份 kirakira-mvu-0。
- 危险:MVU(或未来其它脚本)可能按版本号走特性分支;版本升级行为变化无法从日志看出。动身份逻辑 = 动 MVU 的启动前提(选主失败 MVU 不启动)。

## X10. updateMessageSwipesData(chat_providers)

- 位置:chat_providers.dart「更新单条消息的 per-swipe 变量(MVU setChatMessages 落点)」。
- 谁在用:_handleSetVariables(message 层)与 th_setMessages(setChatMessages 批量 per-swipe 种变量)。
- 危险:这是消息级变量落库唯一通道,并发写(swipes 切换中 + MVU 回写)无锁;整份覆盖式更新,读-改-写竞态会丢变量【疑似】。
