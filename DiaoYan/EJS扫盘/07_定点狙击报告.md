## 一、四个必答问题

### Q1 system_prompt 到底进没进 messages?
**组装端【实证:进】**:正常发送走 `sendMessage → _buildContext()`,其中:
1. 自动生图指令(role=system,条件注入);
2. 世界书条目(`addWorldInfoAt`,role='system')——**但有门槛**:`_findMatchingWorldInfoEntries` 走关键词匹配,条目关键词没命中当前上下文就**根本不进** messages;
3. prompt sections(systemPrompt section,role=`section.role ?? 'system'`,内容取 section.content 或角色卡 systemPrompt);
4. 历史(含开场白)。

**dump 端【实证:有截断陷阱】**:`_logRequest` 每条消息只打 **前 200 字符**,超长以 `...` 截断;Claude 通道更特殊——system 被抽出数组放进顶层 `data['system']`(代码:`firstWhere(role=='system')` + `where(role!='system')`),dump 里单独打一行 `System: $preview`(同样 200 字符截断),messages 列表里看不到它。

→ **"紫水晶729 搜不到"有三种可能,探针前无法定罪渲染器**:
- A. WI 条目关键词未命中,压根没组装进去;
- B. 进了,但短语位于消息第 200 字符之后,dump 截断看不见(**实际已发给模型**);
- C. Claude 通道被抽到 `System:` 行且被截断。

### Q2 有没有任何环节清除 `<%...%>`?
【实证:本链没有】全 lib/ 检索无任何 `<%[\s\S]*?%>` 剥除逻辑(tts_service 的 strip 是 TTS 文本清洗,不在本链)。dist 内部 Mv 处理器会往 ST 的 extension_settings.regex 注入剥 EJS 正则,但只在 GENERATION_AFTER_COMMANDS 触发——我们从不发该事件。**"整段消失"不是清除者干的。**

### Q3 dump 打印在渲染前还是后?
【实证:后】渲染在 `generateWithReasoning / generateStreamWithReasoning` **入口**执行;`_logRequest` 在各 provider 方法内部、requestData 构建后调用 → **dump 是渲染后快照**(受 200 字符截断)。
推论:user 历史消息在 dump 里保留 `<% if %>` 原文 = **渲染确实没改它们**(走了回退);而"system 消失"不能单凭 dump 定罪——见 Q1 三可能。

### Q4 _handleRenderEJS 到底被调了吗?
接线静态完整:initState register → registry.current → RegistryEJSRenderer.render(null 时原样返回)→ `_renderEJSInMessages`(仅两个 WithReasoning 入口)。正常聊天 sendMessage → generateStreamWithReasoning ✓ 经过;continue/regenerate 同样经过。
两个静态盲区只能靠探针:①registry 是否真的 set(现在有 `[EJSD-1a]`);②kick 之后发生了什么(`[EJSD-3/4/5]`)。
另注意:**多模态 user 消息(content 是 List)跳过渲染原样保留**——若带图消息里有模板,天然原文直出。

## 二、Task 2 kick/poll 复核结果

| 检查项 | 结论 |
|---|---|
| realm 错位 | 【静态判定:读写同窗】`.then(function(v){ window.__krRes[id]=... })` 回调函数创建于外层页脚本,按 ES 规范以回调函数自身 realm 执行 → window=外层窗;poll 也读外层窗。但保留怀疑,`[EJSD-4]` 打 `window===parent` 实证(外层 top 里恒 true;打出 false 即错位;若 evalTemplate 明明 resolve 了却完全没有 [EJSD-4] 行,也是错位信号——sendToFlutter 在错误 realm 里不存在) |
| DOM 选择器 | 【实证一致】`#__engineRoomHost` + `iframe[data-frame-id="engine-room"]` 与 createEngineRoom 创建参数完全一致;host 缺失时引擎房根本建不起来(MVU 已在跑说明 host 存在) |
| 就绪时序 | dist 是 jQuery ready 后异步自启,首次手发消息通常晚于挂载;但若首条渲染跑在挂载前,kick 返 -1 **静默**回退宏替换——症状与观察吻合。[EJSD-3] NOT-READY 行会直接暴露 |
| 跨 frame 可访问性 | blob iframe 与外层同源,contentWindow 可达(__emitToEngine 同款模式已在用) |

### 🔴 复核中揪出的新嫌疑(此前手册未列)
**evalTemplate resolve 出 null/undefined → 我们写 `{ok:true,v:''}` → 返回空串 → 内容被清空。**
这能单独解释"system 内容整段不见"(该条走了 evalTemplate 且返回空),同时 user 消息因某种原因走了 -1/超时回退保住原文。`[EJSD-4] vlen=-1` 与 `[EJSD-5] ok vlen=0` 会抓现行。
次要静默面:①evaluateJavascript 对纯 number 返回的序列化形态(idNum 解析容错已做,[EJSD-3] raw= 可见);②poll 返回 JSON 若被插件再包一层,jsonDecode 失败→res=null→静默轮询到 8s 超时([EJSD-5] unparseable/TIMEOUT 行可见,且表现为每条消息慢 8 秒)。

## 四、给人类的一句话操作说明

**发一条普通消息(别带图),然后在日志里按顺序 grep 这五个 tag,对照下表读结果:**

```
grep -E "EJSD-[1-5]" 日志
```

| 你看到 | 结论 → 下一步 |
|---|---|
| 无 `[EJSD-1]` 行 | 渲染层根本没进(生成路径没走 WithReasoning?)→ 把发送方式告诉 agent |
| `[EJSD-1a] registry.current=null` | 聊天页没注册成功 → 查 initState 时序 |
| `[EJSD-2] ... zis=false` 但你确信那条 system 含紫水晶729 | **短语没进 messages**(WI 关键词没命中或放错位置)→ 检查条目关键词/改放 systemPrompt section |
| `[EJSD-2] zis=true` 且 `[EJSD-2r] outLen=0` | 🔴 **evalTemplate 吃了内容返回空** → 真凶确认,agent 修 fail-open 加空串保护 |
| `[EJSD-2r] outTags=0 outLen<原len` | 渲染成功!dump 里看不到是 **200字符截断假象**,内容其实发了 |
| 只有 `[EJSD-3] NOT-READY ejsType=undefined` | dist 未就绪就渲染了 → 需要等 EjsTemplate 挂载(后续修) |
| `[EJSD-3] kick returned id=-1 raw=null` | evaluateJavascript 返回值序列化问题 → 改 kick 返回字符串标记 |
| `[EJSD-4] realm_outer=false` 或 evalTemplate 明明执行却无 [EJSD-4] 行 | 槽写进了错的 window → agent 改槽位置 |
| `[EJSD-5] poll TIMEOUT` 反复出现且发送变慢 | poll 读不到槽(JSON 双层包裹或 realm)→ 看 unparseable 行 head |
| `[EJSD-5] evalTemplate ERR -> macro fallback` | 模板求值抛错,看 err 内容(多为 stub 缺件) |

**验收提醒不变:看请求 dump 里的 messages,不看气泡;气泡里 `<% %>` 原文属预期。**
