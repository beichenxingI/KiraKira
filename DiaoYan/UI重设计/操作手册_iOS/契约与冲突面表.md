## 二、跨块共享 API 契约(签名级别)

### 1. KiraPressable(Block A 产出,B/C/D/F/G 消费)
```dart
KiraPressable({
  required Widget child,
  VoidCallback? onTap,
  BorderRadius? borderRadius,   // 高亮裁切;列表行给 null 即可
  bool scaleEnabled = true,     // 导航项传 false
})
```
行为锁定:按下 → scale 0.97(若启用)+ opacity 0.6,120ms easeOut;
松手即回。**任何块不得修改这两个数值**——要新档位就加命名参数
(如 `pressScale`),不动默认。

### 2. KiraSection inset-grouped(Block A 产出)
```dart
KiraSection({ required String title, IconData? icon, required List<Widget> children })
//   一组一张卡,children 间自动插 0.5px separator,indent 16
KiraSection.plain({ required String title, IconData? icon, required Widget child })
//   组内是一整块(滑块组/表单),不插分隔线
```
D/F/G 必须按语义选形态:**导航行组 = 默认;表单/连续组合 = plain**。

### 3. KiraGroupedTile(Block A 产出)
```dart
KiraGroupedTile({
  IconData? icon, Color? iconBg,    // iconBg 给则画 10 圆角彩块
  required String title, String? subtitle,
  Widget? trailing,                 // 默认 chevron
  VoidCallback? onTap,
})
```
行高标准 44+,标题 17、副 13 tertiary。**它只能在 KiraSection 内使用**,
单独浮在页面上是违规。

### 4. KiraGlassBar(Block A 产出,B 消费)
```dart
KiraGlassBar({ required Widget child, bool enabledBlur = true, BorderRadius? radius })
```
B 按 tab 传值:非聊天 tab `true`,聊天 tab(`/` index 2)`false`(WebView 兼容,DPI 诅咒)。

### 5. Large Title 统一配方(C/D/F/G 消费)
```dart
SliverAppBar.large(
  title: Text(title, style: Theme.of(context).textTheme.displayLarge),
  // AppBarTheme 已配:背色=scaffold、无 tint、centerTitle false、
  // 收缩后 17/w600 由 Material 自动管
)
```
- **禁止**给 `flexibleSpace`、`expandedHeight`、`toolbarHeight` 传自定义值;
- 收缩逻辑全靠 Material 默认,B-T2 的自定义转场不影响它;
- 编辑/表单深页用 `SliverAppBar(pinned: true, title: Text(...))`(非 large)。

### 6. 路由二层化 map(B 产出,C/D/E/G 消费)
见 Block B-T3 表。全文搜索禁用旧路径串:`-settings'` 不得再出现
(注释除外)。push 一律 `context.push(AppRoutes.*)` 常量,**不允许裸字符串**
(已有裸串处由各 Owner Block 顺手清)。

### 7. 弹窗三分类(D-T2 产出,G 复用)
确认→CupertinoAlertDialog;单字段→底部 Sheet;多字段→push 子页。
G 中 ai_config 的弹窗按同一规则迁,**不自创第四种**。

### 8. 状态色(A 产出,全消费)
`statusSuccess/statusWarning/statusError` 是唯一合法状态色来源;
`Colors.green/red/orange` 出现即违建(样本色板等豁免场景必须在代码
注释里写"豁免:……")。

## 三、已知冲突点与解法

| # | 冲突点 | 解法 |
|---|---|---|
| 1 | A-T1 删 `fontSizeLg` 后 B-G 各页报错 | 编译器红=工单;统一迁 `fontSizeXl`(标题)或 `fontSizeHeadline`(行) |
| 2 | A-T4b KiraSection 语义变化,C-T4 设置主页与 mwu 自动变样 | 预期内;这两页在各自 Block 验收 |
| 3 | B-T3 路径二层化后,老收藏的"深链"失效 | 接受(本 App 无 Web 深链需求);`_calcIndex` 前缀判断天然兼容 |
| 4 | KiraSearchBar(A-T5)圆角 30→10,跟角色页设计风格 | C-T1 验收时看完感;若太方,回退 12(radiusCard)而非 30 |
| 5 | CupertinoSwitch 在浅色下 track 色 | active = primary(A-T2 cupertinoOverrideTheme);inactive 由 Cupertino 默认灰,项目不 Override |
| 6 | Hero/容器 Hero 与 B-T2 侧滑转场叠加 | 角色卡片未来做 Hero 时,转场保持侧滑,Hero 独立跑,iOS 同款 |
| 7 | ai_config_screen 外壳 C 改、内部 G 改,两次 commit 同文件 | C-T3 只许动 build 顶层与 banner 装饰,G 再进内部,顺序严格 |
| 8 | model_detection 的"档位品牌渐变"与 B 板 primary 同近 | G-T2 按三色映射(青/紫/AF52DE)执行,别新增第四色 |
| 9 | log_view 新增路由 /settings/data/logs | B-T3 建路由,D 做页面,E 进索引——三块各做一段,顺序 B→D→E |
