# 阶段三挂机执行注意事项(草案 · 供人类审核后下发)

> 沿用上轮突发规则并补"视觉验收"层。本轮改的是布局/配色,
> **dart analyze 绝对不够**——analyze 绿只证明"能编译",不证明"像 iOS"。

---

## 一、沿用的硬规则

1. **同一错误出现 2 次 → 立即回退到上一个 commit 再换方案**,不许第 3 次硬刚。
1a. A-T1(以及任何手册明标"允许红中过渡"的 Task)不适用 error 回退规则,只在其下一个 Task 收尾时判断。
2. **待核实分两类**:
   - 【待核实·观感】:少量"按 10 执行"这类色值/圆角取舍,直接按手册值做,
     完工人眼看,不爽再调;
   - 【待核实·边界】:影响数据/状态/兼容的(如 WebView + BackdropFilter),
     必须先用最小 spike 验证再铺开。
3. **每 Task 一个 commit**,commit message 带 Block/Task 号
   (如 `refactor(core): F-T2 环形图强化`);每 Block 完工打一个 tag
   (`ios-block-a` ... `ios-block-g`)。
4. **聊天域禁区**:`webview_chat_stage.dart`、`screens/chat/*`、
   `widgets/chat/*` 连读都不读;`logprobs_panel.dart` 仅允许 B-T2 在路由表
   搬行。
5. **不新增依赖**;Cupertino 系 + figma_squircle 够。
6. **结构重做类**(标 🔧 的 Task)单独 commit,不与顺手改混提。

## 二、本轮新增的"视觉验收"层(关键补丁)

### 2.1 每 Block 完工必须过"真机/模拟器截图清单"
各 Block 手册末尾已列清单,挂机时按下表执行:
- 用模拟器/真机 `flutter run`,**逐页截图**存到 `DiaoYan/UI重设计/验收_ios/<Block>/`;
- 深色为必跑;浅色**至少**每个 Block 抽 3 页;
- 截图命名 `<block>_<page>_<mode>.png`,例如 `c_settings_dark.png`。

### 2.2 结构重做三兄弟(B/C)存档后继续推进(不停等人类)

B(导航外壳)、C(主导航4页)完工后:
1. 各自打 tag(`ios-block-b` / `ios-block-c`),并额外打一个组合存档
   tag `ios-bc-checkpoint`,commit message:
   `docs: B/C 骨架完成存档,供人类醒来验收回档基准`。
2. **不停下等待**——直接按 A→…→G 顺序继续推进 D/E/F/G。
3. 继续前,先跑一遍 §2.3"这不对劲"自检清单。若扫出**硬伤**
   (深色卡片残留投影 / 水波纹没换干净 / 大标题不收缩 / CupertinoSwitch
   变绿等**确定性错误**,非"审美判断"),先在 B/C 内修掉再继续;
   修 2 次仍不过按回退规则处理,并在日志标记"B/C 带伤继续,人类需重点看 X"。
4. **审美层面的"对不对味"不由 Agent 判断**——那是人类醒来的活。
   Agent 只负责"骨架无硬伤"就继续盖楼。

人类醒来:验 `ios-bc-checkpoint` 的 B/C 截图/真机效果。
- 对味 → D/E/F/G 白赚,直接进终审微调。
- 不对味 → `git reset --hard ios-bc-checkpoint` 之前的基线重来 B/C,
  D/E/F/G 一并作废(本就建立在其上,无额外损失)。

### 2.3 自检"这不对劲"清单(挂机时随时对照)
- 深色下:卡片还有投影?→ 去找出哪里的 boxShadow 没清。
- 文字看着发灰而非"半透明白"?→ 检查是否用了旧 textSecondary。
- 行分隔是 1px 实线?→ dividerTheme 没生效或行内手写了。
- 按压还有水波纹?→ 那处 InkWell 漏换。
- 大标题不收缩/跳变?→ SliverAppBar.large 嵌套错了(多半外套了 Scaffold.appBar)。
- CupertinoSwitch 变绿?→ activeTrackColor 没吃主题。

## 三、节奏与回退

1. 顺序严格 A → B → C → D → E → F → G;E 依赖 C/D 的骨架与登记,
   F/G 可并行思考但同一 Agent 串行做。
2. 每个 Block 内部按手册 Task 顺序;A-T1 是"红中过渡态"(analyze 允许红),
   到 A-T2 应回绿。
3. 任一 Block 真机验收"差得离谱"(比如大面积白边/黑块/对比度事故),
   **git reset 回本 Block 起点 tag 重来**,不在错骨架上继续盖楼。
4. 单页三次都套不进 D-T0 模板(如 vector_storage 这种弹窗大户),
   允许该页降级为"只 Sliver 化 + 色清,弹窗留旧样但圆角统一",
   并在 Block D 验收报告里如实标记"半完成",由人类拍板是否补。

## 四、交付尾声

- 全部 Block 完工:`dart analyze` 零 error、`flutter test`(若项目有)过、
  截图目录满编、剩余 TODO(i18n) 清单汇总成文给人类。
- 最后 commit:`docs: iOS 化整体验收汇总`。
