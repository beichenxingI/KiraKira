# P3 设计 — 消息级 iframe(零改动,纯文档)

> 目标:为「一条气泡内多前端 + 悬浮球」的富交互提供共同地基,并根治消息间 ID 互撞。
> 本文只出设计,不动代码。关键锚点均来自 `assets/chat/chat_stage.html` 与 `backup/c1-alpha-failed`。

---

## 一、为什么要消息级 iframe(背景实锤)

1. **`dupIds=464`(真机日志)**:消息正文里含 `id="xxx"` 的 HTML,经 `innerHTML` 注入主文档后变成真实 DOM 元素,消息与消息之间同名 id 大量互撞。P1-C1 只解决了「消息撞 shell 那 5 个保留 id」,消息互撞**只能靠作用域隔离根治** —— 每条消息一个 iframe,其内部 DOM 天然与主文档及其它消息隔离。
2. **现在的 card 已经是 iframe,但只有"纯 HTML 卡"才进 iframe**(`if (isRichHtml(m.html))` 1087);非 rich 消息走 `wrap.innerHTML` 注入主文档(1113–1116)。两者机制割裂,是 P3 要统一的点。

## 二、消息级 iframe 设计

### 2.1 每条消息独立 iframe 的作用域隔离

- 每个气泡 = 一个 `iframe.msg-frame`,`srcdoc`(或 blob)承载该消息的完整 HTML + 样式 + 脚本。
- 作用域隔离收益:
  - 消息内部的 `id`、`class`、全局变量、`localStorage`/`sessionStorage` 访问(配 injectBridge 已有覆盖)、事件监听都封在 iframe 内,不污染主文档。
  - 消息内容里的 `id="model-sheet"`/`id="root"` 不再能命中 shell 或其它消息(彻底根除 dupIds 的消息互撞类)。
- 高度自报告:iframe 内已有 `__cardHeight` 回传机制(`parent.postMessage({__cardHeight:true,id:_id,height:h})` 572 行),外层已有接收 + 设高(757/767)。可复用到所有消息 iframe。

### 2.2 桥如何通进 iframe(TavernHelper API 转发)

现有机制已经存在,且**可原样复用**:

- iframe 内 `injectBridge`(489)注入 `_TH`(TavernHelper 命名空间),所有 API 走 `__thCall(method, args)`(590),发 `parent.postMessage({__thRequest:true, frameId, rid, method, args})`(596)。
- 外层主 script 监听 message(id 中转 `__thRequest` → 调 `__sendRequest`(桥) → Flutter → 结果 `parent.postMessage({__thResponse,...})` 回 iframe)。
- 即:ifream 内脚本只需要 `window.TavernHelper`(`__thCall` 系列),就能通过"postMessage 中继 → 桥 → Flutter"拿到酒馆助手 API 结果。**P3 不需要新造桥,只需把现有 injectBridge 的 `_TH` 注入扩展到"每条消息 iframe"即可**(现在只注入到卡 iframe 与引擎房)。

### 2.3 `dupIds=464` 如何被 iframe 化根治

- 根因是消息内容经 `innerHTML` 进主文档后,其 `id` 成为主文档真实 id。iframe 化后,消息内容只存在于 iframe 的 document 内,其 `id` 永不进入主文档的 `document.getElementById` 作用域 → 消息之间、消息与 shell 之间不再互撞。
- 残余风险:iframe **内部**一条消息自己若含两个同名 id,仍是它自身作用域内的问题(消息作者自己写重复 id),不影响其它消息/shell,危害等级已从"跨消息污染"降到"单消息自伤"。

## 三、α 那轮翻车的复盘

读 `backup/c1-alpha-failed` 的 5 个 commit(`ed53b33`~`9beb998`)与 diff,翻车点是复合的:

1. **直接致命伤 = JS 语法错**:降级占位代码里写了 `_pre.textContent = (((m && m.prose) || '') + '\n' + ...)`(backup 第 4111 行)。那个 `'\n'` 在 **Dart 三引号字符串**里被 Dart 重写成**真换行**,于是注入进 shell 的 JS 变成单引号字符串跨行 → 整个主 `<script>` 块 SyntaxError。这一处(P0 阶段已用 `node --check` 实锤抓到 `SyntaxError: Invalid or unexpected token`)导致主脚本里 `setMessages`/`createEngineRoom`(引擎房第三次点火)/所有 bridge handler 全部失效——即"α 全灭"。
2. **结构性激进**:同一条消息里塞了"同气泡多前端(segs)" + "围栏保护" + "单消息 iframe" 多个大改动,还改了渲染分流与序列化字段(新增 `segs`),超过"只加保护"边界。
3. **没有语法检查链**:当时没有"改 JS 前 `node --check`"这把尺子,`'\n'` 错误直接上了真机。

**这次 P3 怎么避免:**

- **P0 已补上尺子** (`tool/check_chat_stage.dart`,已自证能抓错);P3 所有 JS 改动前必过它。
- **分层落地,不一步到位**:P3 只做"消息级 iframe 承载 + 复用现有桥转发",**不**同时引 segs、不动渲染分流、不动序列化字段。每个 Task 一个可单独 revert 的 commit(沿用 P1-A/B/C 的纪律)。
- **转义铁律**:任何进 iframe/shell 的 JS 字符串,凡在 Dart 侧拼接,绝不用字面 `'\n'` 之类的 Dart 转义表示 JS 换行;JS 换行用真换行或 `String.fromCharCode`/字符串拼接,并让 `node --check` 兜底。
- **不复制 α 的"外层 catch 抹页"回归**:P1-B2 已把 `root.innerText='ERR'` 抹页逻辑删掉;P3 复刻时要守住这个结论。

## 四、P3 与 P2(diff/窗口化)的冲突点

1. **diff 渲染**:把气泡从主文档 DOM 变成 iframe 后,P2 的"按 id 对 DOM diff"要改成"按 id 对 iframe 集合 diff"(增删 iframe 元素,而非增删内部节点)。iframe 内部不 diff(**iframe 内容变了就重建 iframe**,或走 srcdoc 局部更新)。这比现在"同 id 同 html 跳过卡片"更彻底——iframe 天然是"整体替换"单位。
2. **窗口化**:每条消息一个 iframe,窗口化粒度自然变成"摘除视口外消息的 iframe"(与现有 iframe 虚拟化 914–968 同构,只是从 card 推广到全部消息)。占位保高的高度源 = 每消息 iframe 的 `__cardHeight` 回传,现成。
3. **顺序建议**:P2 的 diff 与 P3 的 iframe 化互相影响设计。**建议 P3 先于 P2 或合并评估**:一旦 iframe 化,很多 P2 的"卡片状态保持"难题(重建 iframe 丢脚本)反而简化(消息 = 一个整体可替换单位)。但 P3 改动面大,需真机验证富交互;P2 当务之急(修 reroll 抖动)可先独立落地。

## 五、我没能验证的部分

1. **α 翻车的确切完整因果**:我只实锤了 `'\n'` 语法错导致主脚本崩(那是"全灭"的直接凶手),但 backup 里是否还有别的运行级 bug 共同致因,静态读 diff 只能看出一部分,看不到当时真机全貌。
2. **消息级 iframe 的性能/内存**:350 个消息 = 350 个 iframe 的上限代价未测(现在 card iframe 只有 19 个),真机 profile 前不建议全量铺开;需先以"一条消息试运行"验证桥转发、高度回传、滚动体验。
3. **iframe 内 `window.TavernHelper` 依赖的完整性**:现有 `_TH` 注入含世界书/变量/生成等 stub;消息级 iframe 是否需要同样完整的 API 面,或只需子集,取决于悬浮球/多前端的实际需求,未定。
4. **跨 iframe 的共享作用域诉求**:α 的 C1-T2 曾因"共享作用域对齐上游"而选整消息单 iframe;若悬浮球要求"多前端共享脚本作用域",纯消息 iframe 会打破它,需在 P3 里权衡"隔离"与"共享"的取舍——这个矛盾本文只点出,未解决。
5. **dupIds=464 的具体构成**:引用真机日志数字,无法复现拆分「消息互撞 vs 消息撞 shell」的确切占比(P1-C1 增补里判断"绝大多数是消息互撞"是背景结论,非我静态可证)。
