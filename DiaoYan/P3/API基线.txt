## 一、最重要的一条:读必须同步

官方声明(`@types/function/variables.d.ts` 等):
```ts
declare function getVariables(option: VariableOption): Record<string, any>   // 同步返数据
declare function getAllVariables(): Record<string, any>                      // 同步
declare function getCurrentMessageId(): number                               // 同步
declare function getLastMessageId(): number                                  // 同步
declare function substitudeMacros(text: string): string                       // 同步
declare function replaceVariables(variables, option): void                    // 同步
```

MVU 实现(`src/function/global/index.ts`):
```ts
getMvuData: e => getVariables(e) as MvuData      // 无 await → 读必须同步
replaceMvuData: (d,o) => replaceVariables(d,o)   // 原样返回
```

原作者注释(实证,可依赖):
> **旧酒馆助手的 replaceVariables 是异步函数, 因此需要返回 Promise**

**→ 结论:读侧必须同步返数据;写侧返 Promise 是被容忍的。**

**我们现状:** `_TH.getVariables`(`chat_stage.html:655`)走 `__thCall` → postMessage → **返 Promise**。

**→ 风险:直接把异步包装挂成官方名字 = 批量制造静默 bug。**
卡 `typeof getVariables === 'function'` 判真 → 调用 → 拿到 Promise →
`v.stat_data` 为 `undefined` → 静默走错分支,不报错不留痕。
**这比函数缺失危险得多**(缺失会被 `chat_stage.html:896` reject 并被 CARD-ERR 抓到)。

**→ 铁律:P3-D 完成同步快照之前,不许挂任何官方名变量读函数到全局。**

## 二、`window.Mvu` 的真实挂载机制

`src/function/global/index.ts` 的 `initGlobals()`:
```ts
_.set(window.parent, 'Mvu', mvu);
eventEmit('global_Mvu_initialized');
```

要点:
1. **MVU 自己挂,不需要宿主提供挂载函数。**
   `initializeGlobal` / `waitGlobalInitialized` 在 beta 源码中**不存在**
   (grep 零命中);那是 `@types/function/global.d.ts:14` 描述的新约定,
   **实现未跟上。以源码为准。**
2. **挂到 `window.parent`** —— MVU 假设自己在 iframe 内。
   我们 MVU 在引擎房(iframe)→ **`Mvu` 落到 `chat_stage.html` 主文档**,
   不是引擎房自己。**P3-E 的转发起点是主文档。**
3. **前提 `store.should_enable`(Pinia watch)。为假则永不挂载且完全静默。**
   `store.ts` 引 `registerAsUniqueScript` → 选主失败就不启动(对应已知"关卡三")。
4. 挂好后 emit `'global_Mvu_initialized'`,可作为就绪信号。

## 五、YAML 必补(已实证)

`MagVarUpdate/util/common.ts` 用 `YAML.stringify` 与
`YAML.parseDocument(content,{merge:true}).toJS()`,**却没有 import YAML**;
靠 `tsconfig.json` 的 `"types":["yaml"]` + `"allowUmdGlobalAccess":true` 当 UMD 全局放过
→ **webpack 不打包,宿主必须提供全局 `YAML`**。

`parseString` 就在该文件,`variable_init.ts:13` 引它解析 `[initvar]`
→ 完整对上引擎房实测报错 `解析世界书条目'[initvar] 初始'失败: ReferenceError: YAML is not defined`。

**必须用 `yaml@2`(对齐 `^2.8.0`),不是 js-yaml** ——
调的是 `parseDocument().toJS()` 与 `stringify(v,{blockQuote:'literal'})`,js-yaml 无此 API。
**注入位置:引擎房必须有(MVU/EJS 都在那跑),card iframe 顺带。**

另:EJS 侧也需要 —— `function_call.ts:205` 是模板字符串
`<%= YAML.stringify(getvar('stat_data'), ...) %>`,由 ST-Prompt-Template 执行,不经 webpack。
