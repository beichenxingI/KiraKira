# P5-2：精确根因与最终施工方案

## 结论先行

本轮实际读取了 `DiaoYan/PiuPiuCard_《道渊》v5.2.json`。结果与 P5-1 更正后的文件名一致，但**该卡片中没有用户指定的“道渊脚本”**：

- `data.extensions.regex_scripts[6].replaceString`：182939 字符，是 MVU 状态栏的 HTML/CSS/普通浏览器脚本；只找到 `setInterval`，用途是十秒阅读倒计时。
- `data.extensions.piupiu_regex.scripts[6].replaceString`：同一类 MVU 状态栏 HTML；同样没有 TavernHelper 世界书调用。
- `data.character_book.entries[229].content`：MVU 更新格式说明，不是 JavaScript。
- 全文件 ASCII 字符串计数：`setInterval=2`，`getWorldbook=0`，`replaceWorldbook=0`，`EjsTemplate=0`，`extensionSettings=0`。
- 卡片中未出现 `四项通知未全开`、`输出格式强调未开启`、`状态栏模式有 N 项误开` 这些完整报警文本；中文字段在当前 PowerShell 输出中有编码显示问题，但 ASCII API 名称计数为零。

因此铁律要求的“每条具体 if 条件、真实调用频率、完整脚本提取”在当前仓库**无法完成**。把这些条件写成确定结论会是编造。下面明确区分已证实事实、可验证推测与可直接施工的宿主修复。

## 1. 实际提取到的关键脚本内容

### 1.1 唯一 `setInterval`

路径：`.data.extensions.regex_scripts[?].replaceString` 与 `.data.extensions.piupiu_regex.scripts[?].replaceString`（两个内容重复）。关键代码为：

```js
var countdown = 10;
var countdownDone = false;
var timer = setInterval(function() {
    countdown--;
    if (countdown <= 0) {
        countdownDone = true;
        clearInterval(timer);
        tryUnlock();
    } else {
        daoyuanLetterConfirm.textContent = '请阅读全部 (' + countdown + 's)';
    }
}, 1000);
```

它只服务于自定义命运模式授权前的十秒倒计时；没有世界书、MVU 通知检查或“随 AI 输出/额外模型”切换逻辑。

### 1.2 卡片确实包含的 MVU 格式

路径：`.data.character_book.entries[229].content`。内容要求回复末尾输出 `<UpdateVariable>`、`<Analysis>` 和 `<JSONPatch>`，并要求所有分类逐项处理；这解释了卡片为什么需要 MVU 变量更新，但没有实现宿主 API，也没有四条报警的判断式。

### 1.3 状态栏脚本的能力边界

两个大 `replaceString` 均是注入 HTML。可见 DOM 逻辑包括状态栏、模式选择、预设按钮、自定义命运模式、画布动画和 `setInterval` 倒计时；当前 JSON 中不存在 `getWorldbook` 或 `replaceWorldbook` 调用。因此不能据此推导世界书条目的字段、误开计数或模式切换 API。

## 2. 道渊四条报警：精确性审计

| 报警 | 脚本真实 `if` | 期望数据 | 实际数据 | 结论 |
|---|---|---|---|---|
| 四项通知未全开 | 当前卡片未找到该判断 | 无法从卡片确定四项键名和值 | 探针有三项 true、一项 `变量更新出错:false` | **只能确认探针状态不全为真，不能确认脚本用了 `every(Boolean)`** |
| 提示词模板未安装 | 当前卡片未找到判断 | 无法确认是 `extensionSettings.EjsTemplate` 还是别的对象 | 探针 `ejs:false` | **只能说明探针检测对象为假/缺失，不能确认检测对象** |
| 输出格式强调未开启 | 当前卡片未找到判断 | 无法确认世界书名称、条目 comment/content 或 enabled 字段 | 脚本房世界书方法均 undefined | **方法缺失是宿主事实，但不能证明报警由此产生** |
| 状态栏模式有 N 项误开 | 当前卡片未找到计数代码 | 无法确认哪些条目属于模式集合、按 name 还是 enabled 计数 | 探针未提供 N 或条目快照 | **不可判定** |

### 可证实的宿主原因

P5-1 探针运行在独立脚本房 iframe，`W=frame.contentWindow`。独立脚本房没有自动继承引擎房的 TavernHelper 门面；当前宿主只在引擎房注入 `getWorldbookNames/getWorldbook/replaceWorldbook` 等方法。因此探针输出：

```text
getWorldbookNames=u,getWorldbook=u,replaceWorldbook=u,...
```

是可靠事实。它足以导致任何直接调用这些裸全局方法的脚本失败，但**不能替代缺失的道渊原脚本**来确定四条报警的具体来源。

## 3. 切模式崩溃

卡片中找到的是自定义命运/普通模式 DOM 切换，未找到“随 AI 输出/额外模型”或 TavernHelper 世界书调用。宿主中可证实的模型方案切换链为：

1. WebView `chat_stage.html:384-388` 发送 `switchConfig`。
2. Flutter `webview_chat_stage.dart:804-826` 调用 `setActive`、重置请求并重新获取模型。
3. 失败时 `configId` 缺失会直接返回；该异步段的异常保护不完整。

因此黑屏的**已证实施工点**是 `switchConfig` 异步链必须统一 `try/catch` 并向 WebView 回送失败状态；至于是否是 `replaceWorldbook`、`generateRaw` 或卡片内部异常，当前没有崩溃栈和原脚本，不能定案。

## 4. 预设球根因

已证实链路：

- 点击与 payload：`assets/chat/chat_stage.html:2045-2060`。
- 桥发送与回调：`assets/chat/chat_bridge.js:47-100`。
- Dart 匹配：`lib/presentation/screens/chat/webview_chat_stage.dart:1699-1725`。
- provider 更新：`lib/data/models/prompt_manager.dart:313-333`。
- UUID 生成而非名称随机化：`lib/presentation/providers/prompt_manager_providers.dart:202-225`。

主工程没有修改 section `name` 的随机代码；已知随机值是预设 UUID。最可疑但尚未现场证实的断点是外部脚本传入重复的无 `identifier` section：Dart 要求按 `type` 且 `identifier=null` 只能匹配一个，多于一个会拒绝写入；回显也会因 `type/identifier/name` 不一致失败。

### 直接施工

1. 在 `webview_chat_stage.dart:1699-1725` 保留“匹配数必须为 1”，但增加日志：`presetToggle request identifier/type/name/matchCount`，拒绝时把匹配数回送 JS。
2. 在 `chat_stage.html:2045-2060` 点击时记录 section 的完整稳定标识，目标状态由当前对象计算，不用 name 作为主键。
3. 在 `prompt_manager.dart:313-333` 强制所有导入 section 在缺失 identifier 时生成稳定 UUID 并持久化；更新只按 identifier。不要用 `Random` 改 name。
4. 在 provider 回显前校验 identifier 唯一；重复时显示错误而不是把同一名称写入全部条目。

这些是基于现有源码可施工的修复；“所有条目改成同一随机名”的具体产生语句仍需真实外部 preset script 才能定位。

## 5. 道渊最终施工方案（按优先级）

### 5.1 脚本房注入 TavernHelper

文件：`assets/chat/chat_stage.html:1792-1885`，脚本 iframe 创建后、执行外部脚本前，注入与引擎房同版本的 facade。不能只在 `tavern_helper_facade.dart` 注入引擎房。

最低契约必须在脚本房存在：

```js
window.getWorldbookNames = function () { return __thCall('getLorebooks', []); };
window.getWorldbook = function (name) { return __thCall('getLorebookEntries', [name]); };
window.replaceWorldbook = function (name, entries) {
  if (!Array.isArray(entries)) return Promise.reject(new Error('entries must be array'));
  return __thCall('setLorebookEntries', [name, entries]);
};
```

实际工程应复用现有 facade 生成器，不复制第二套协议。验证：脚本房探针必须输出 `getWorldbookNames=f,getWorldbook=f,replaceWorldbook=f`，调用日志必须出现对应 `__thRequest`。

### 5.2 EJS

当前卡片没有 EJS API 字符串，不能断言所需字段。不要伪造 `extensionSettings.EjsTemplate` 的内部结构。应先让探针打印：

```js
JSON.stringify({hasST:!!window.SillyTavern, extensionSettings:Object.keys((window.SillyTavern||{}).extensionSettings||{}), ejs:window.EjsTemplate||null})
```

若真实脚本随后确认读取 `SillyTavern.extensionSettings.EjsTemplate`，再按其实际字段补齐；当前只能施工为空安全对象，不能声称已满足模板安装。

### 5.3 MVU 通知与世界书

不要把 `变量更新出错:false` 强行改成 true。它是状态，不是配置开关；强改会掩盖真实错误。先增加 MVU 事件/异常日志，确保 `stat_data` 快照到达后才挂载 `window.Mvu`（现有门控：`chat_stage.html:805-823`）。世界书读写必须返回真实数组并保留条目字段，不能用空数组假装安装成功。

### 5.4 切模式防崩溃

文件：`lib/presentation/screens/chat/webview_chat_stage.dart:804-826`。将方案切换的整个异步流程包在 `try/catch`，失败时发送 `showModelSwitchError`，并保证 loading 状态、WebView 状态和当前 config 不被半更新。每次切换最多触发一次 fetch；禁止脚本轮询触发重复切换。

由于当前卡片没有该模式 API，不能给出“replaceWorldbook 改为某调用”的虚假代码。

## 6. 性能优化

当前卡片的已知轮询只有十秒倒计时，1 秒一次，确认后 `clearInterval`；它不是“开球后持续卡顿”的证据。宿主应对外部脚本建立定时器预算：记录每个 iframe 的 `setInterval` 创建/清除，限制状态刷新为事件驱动；世界书读取/写入加 100–250ms debounce，写入串行化；状态栏更新只在 MVU `VARIABLE_UPDATE_ENDED` 后重绘；销毁 iframe 时清理全部 timer、ResizeObserver 和 listener。

## 7. 合并验证探针

插入位置：`assets/chat/chat_stage.html` 的脚本房探针附近（现有 `chat_stage.html:1836-1848`）。探针必须通过 `parent.postMessage({__thLog:true,text:...})` 输出，不能依赖控制台：

```js
(function () {
  var st = window.SillyTavern || {};
  var es = st.extensionSettings || {};
  var th = ['getWorldbookNames','getWorldbook','replaceWorldbook'];
  var checks = {
    iframe: location.href,
    mvuSettings: !!es.mvu_settings,
    ejsObject: !!(st.extensionSettings && st.extensionSettings.EjsTemplate),
    tavernHelper: th.reduce(function (o, k) { o[k] = typeof window[k]; return o; }, {}),
    mvu: typeof window.Mvu,
    statData: !!(window.__thVars && window.__thVars.message && Object.keys(window.__thVars.message).length),
    timers: typeof window.__kiraTimerCount === 'number' ? window.__kiraTimerCount : 'uninstrumented'
  };
  parent.postMessage({__thLog:true,text:'[探针验证] '+JSON.stringify(checks)}, '*');
})();
```

目标日志：

```text
[探针验证] {"iframe":"...","mvuSettings":true,"ejsObject":true,"tavernHelper":{"getWorldbookNames":"function","getWorldbook":"function","replaceWorldbook":"function"},"mvu":"object","statData":true,"timers":0}
```

其中 `ejsObject` 只有在真实道渊脚本确认该对象为依赖时才是硬性通过项。运行：

```powershell
flutter run 2>&1 | Select-String -Pattern "探针验证"
```

预设球另加一条宿主日志：

```text
[探针验证] presetToggle identifier=<id> type=<type> name=<name> matchCount=1 next=<true|false> echoed=<true|false>
```
