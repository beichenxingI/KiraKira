| 问题 | 根因 | 后果 |
|---|---|---|
| A | 脚本房↔主文档事件中继形成闭环 | 每秒数百上千次 postMessage；`[选主]` 等日志刷屏；菜单/弹窗卡顿 |

## 2. 修复 A：断环（一行代码）

文件：`assets/chat/chat_stage.html`，事件中继循环内（约 994 行）。

**修复前：** 引擎房 MVU 事件到达主文档后，主文档向**全部**非引擎房 iframe 转发；若其中某个 iframe（脚本房）再把它投回主文档，主文档又向全部 iframe 转发……形成闭环：

```javascript
var cards2 = document.querySelectorAll('iframe[data-frame-id]:not([data-frame-id="engine-room"])');
for (var mi = 0; mi < cards2.length; mi++) {
  if (cards2[mi].contentWindow) {
    cards2[mi].contentWindow.postMessage({ __thEvent: true, type: d.type, args: d.args || [] }, '*');
  }
}
```

**修复后：**

```javascript
var cards2 = document.querySelectorAll('iframe[data-frame-id]:not([data-frame-id="engine-room"])');
for (var mi = 0; mi < cards2.length; mi++) {
  // 跳过事件来源帧,防止脚本房↔主文档无限循环
  if (cards2[mi].contentWindow === e.source) continue;
  if (cards2[mi].contentWindow) {
    cards2[mi].contentWindow.postMessage({ __thEvent: true, type: d.type, args: d.args || [] }, '*');
  }
}
```

**就这一行：** `if (cards2[mi].contentWindow === e.source) continue;`

语义：事件来自哪里就不再回投哪里。事件中继的语义本身就是"转发给其他卡片"，回投来源帧没有业务意义，只会重新触发来源帧的事件分发从而制造下一轮循环。

## 3. 修复 B：等待 loadChat 完成

文件：`lib/presentation/screens/chat/webview_chat_stage.dart`，`initState` 内 addPostFrameCallback。

**修复前（425-433）：**

```dart
ref.read(activeChatProvider.notifier).loadChat(widget.chatId); // 没有 await!
await Future.delayed(const Duration(milliseconds: 350));
if (!mounted) return;
setState(() => _webViewMounted = true);
```

**修复后（440-445）：**

```dart
// [P5-7B] 等 loadChat 真正完成,确保 character 数据就绪后再挂 WebView
await ref.read(activeChatProvider.notifier).loadChat(widget.chatId);
// 延迟挂载 WebView:让入场这段时间保持纯 Flutter(无 WebView 重活),动画/遮罩流畅
await Future.delayed(const Duration(milliseconds: 350));
if (!mounted) return;
setState(() => _webViewMounted = true);
```

`loadChat`（`chat_providers.dart:171`）是 `Future<void>`，包含多段异步：`getChat` → `getCharacter` → `getMessages` → `loadLocalVariablesFromPrefs` → group chat 成员加载。不 await 时 350ms 定时先到，WebView 挂载后 `_injectPresetScripts` 读到的 `character` 仍是旧卡 → 注入旧卡脚本或空脚本。await 后挂载时机天然在数据就绪之后，350ms 的"入场动画留白"语义保留。

## 4. 修复 B 补充：注入前校验

`_injectPresetScripts`（289-302）开头新增两道守卫：

```dart
Future<void> _injectPresetScripts(InAppWebViewController c) async {
  // [P5-7B] 校验: 确保 provider 中的 chat 与本 widget 匹配,防止切卡竞态注入错误脚本
  final currentChat = ref.read(activeChatProvider).chat;
  if (currentChat?.id != widget.chatId) {
    debugPrint('[脚本注入] 跳过: provider中的chat(${currentChat?.id})与widget.chatId(${widget.chatId})不匹配');
    return;
  }
  final prefs = ref.read(sharedPreferencesProvider);
  final character = ref.read(activeChatProvider).character;
  if (character == null) {
    debugPrint('[脚本注入] 跳过: character为null');
    return;
  }
  ...
```

意义：`_injectPresetScripts` 还有 WebView `onLoadStop`（625）与 bridge 回调（813）等异步入口，即使挂载时序仍有偏差，任何路径在注入前都要确认"provider 中的 chat 确实是我这个 widget 的 chat"，否则直接跳过。

## 5. 修复 B 补充：character 变化监听（自愈）

字段（91）：

```dart
ProviderSubscription<String?>? _charSub; // [P5-7B] character 变化自愈监听
```

`initState` 末尾（447-459）：

```dart
// [P5-7B] 自愈: character 变化时重新注入脚本,防止时序竞态注入旧卡脚本
_charSub = ref.listenManual(
  activeChatProvider.select((s) => s.character?.id),
  (previous, next) {
    if (next != null &&
        next != previous &&
        _webViewMounted &&
        _controller != null) {
      debugPrint('[脚本监听] character变化: $previous → $next, 重新注入');
      final c = _controller;
      if (c != null) _injectPresetScripts(c);
    }
  },
);
```

`dispose`（498）：

```dart
_pmSub?.close();
_charSub?.close(); // [P5-7B] character 变化自愈监听
```

监听条件缺一不可：character 变化、非首次通知、WebView 已挂载、controller 存在。触发时重新注入，覆盖"注入发生在新数据落库之前"的残余竞态窗口。
